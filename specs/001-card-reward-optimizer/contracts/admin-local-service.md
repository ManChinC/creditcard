# Contract: 管理員本機服務

依 AD-004、FR-033、FR-034、FR-041、FR-042、FR-045。端點路徑與格式為 `[TBD]`，本檔只規定行為。

## 連線限制

- 僅綁定本機位址，只接受本機連線（FR-041）。
- 驗證請求來源，避免瀏覽器中其他網頁呼叫本機服務（FR-041）。
- 每次登入產生一次性令牌；請求須帶有效令牌（FR-041）。
- 傳輸是否使用 TLS：`[CONFLICT?]` 見 plan.md「待決定的閘門項目」第 1 項。
- 不隨公開網站部署，不對外提供入口（FR-033）。

## 登入與憑證

1. 管理員以本機解鎖驗證登入（FR-033）。
2. 登入後由管理員指定憑證檔位置；系統僅可讀取該單一檔案（FR-034）。
3. 以管理員密碼衍生金鑰解密，解密後憑證只存記憶體，閒置自動清除（清除時機 `[TBD]`）。
4. 憑證不得出現在日誌或畫面（FR-034）。
5. 忘記密碼：可重設，但舊憑證檔無法解密，須重新輸入並加密保存；確認本人方式 `[TBD]`（FR-033）。

## 送出至外部 LLM

1. 管理員提供自行整理好的通路表格；系統不解析原始明細（FR-042）。
2. 送出前顯示實際內容並由管理員確認；內容未變且已確認者可不再確認，有變動須再確認（FR-028）。
3. 送出內容僅限彙整後的通路表格，可含單筆達門檻的大額項目（類別與金額）；MUST NOT 含逐筆明細、商家明細、完整卡號（FR-019、FR-027）。
4. LLM 回傳結果直接帶入，不需人工複製貼上（FR-042）；LLM 僅作說明與解讀，金額由程式計算（FR-013）。
5. 僅限已登入且近端呼叫者（FR-045）；其他一律拒絕。

## 草稿與發布

- 蒐集發卡行公開資訊產生「待確認」草稿，管理員確認後才發布（FR-021）。
- 草稿標示來源與查證日期；無法判斷的欄位顯示「官網沒有寫」或未知（US5 情境 3、4）。
- 發布產物僅為 [published-reward-data.md](published-reward-data.md) 所述 JSON 與公開網頁。
