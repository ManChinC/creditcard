# Contract: SDK 操作與存取宣告

依 FR-043 至 FR-046、FR-049：每個操作在程式內宣告 `accessRequirement` 與 `protectionLevel`，不由呼叫端宣稱。入口先檢查 accessRequirement，需登入者驗證 accessToken，再檢查 protectionLevel；任一失敗即拒絕（預設拒絕）。

宣告值的集合（例如 protectionLevel 有哪些等級）：`[TBD: spec 未定義]`。下表僅標示「匿名」與「已登入且近端」兩類，已由 FR-045 規定。

## 公開層操作（瀏覽器內 SDK，匿名）

| 操作 | 對應需求 | 存取 | 備註 |
|---|---|---|---|
| 驗證並預覽貼上的彙整結果 | FR-001、FR-025 | 匿名 | 通過後須使用者確認才寫入 |
| 智慧提問下一題／提交回答 | FR-023 | 匿名 | 每次回應 30 秒內為目標（SC-009） |
| 通路查詢 | FR-007、FR-035、FR-051、FR-053、FR-055 | 匿名 | 輸入通路與支付方式，可輸入商家名稱；回傳該用的卡、是否需領券、月上限說明、各卡指定商家 |
| 信用卡健檢 | FR-009、FR-010 | 匿名 | 程式比對；金額由程式計算 |
| 新卡試算 | FR-011、FR-012 | 匿名 | 缺漏欄位須指出 |
| 情境推薦／候選卡挑選 | FR-047 | 匿名 | 為健檢與新卡評估的延伸 |
| 載入並驗證公開回饋資料 | FR-048 | 匿名 | 失敗或過期時告知資料狀態（US3 情境 3） |
| 匯出備份／一鍵清除／完整刪除 | FR-017、FR-050 | 匿名 | 備份不加密，匯出前提示 |
| 標記優惠「已領」／本機覆寫回饋規則 | FR-021、FR-022 | 匿名 | 僅本機，不上傳 |

公開層**不具備**任何呼叫 LLM 或讀取憑證的操作（FR-038、FR-045）。

## 管理員層操作（本機服務）

| 操作 | 對應需求 | 存取 | 備註 |
|---|---|---|---|
| 登入／解鎖 | FR-033、FR-041 | 本機連線 | 每次登入產生一次性令牌；忘記密碼重設見 FR-033 |
| 指定憑證檔位置並解密 | FR-034 | 已登入、近端 | 只可讀取該單一檔案 |
| 載入管理員自行整理的通路表格 | FR-042 | 已登入、近端 | 系統不解析原始明細 |
| 檢視並確認送出內容 | FR-028 | 已登入、近端 | 首次確認；內容變動須再確認 |
| 送出至外部 LLM 並帶入結果 | FR-019、FR-042 | 已登入、近端 | 僅彙整後的通路表格 |
| 檢視、確認、退回草稿；發布公開 JSON | FR-021、FR-033 | 已登入、近端 | 草稿標來源與查證日期 |

## 拒絕行為（FR-046）

- 無效或過期 accessToken、protectionLevel 不足、非近端呼叫、未宣告存取規則，一律拒絕。
- 錯誤回應不得洩漏內部細節；記錄不含個人資料的拒絕紀錄。
- 驗證邏輯一律交由 Validator（見 [validator-contract.md](validator-contract.md)），操作本身不自行判斷。

## 稽核對應

SC-012 的測試集：無 token、過期 token、竄改 protectionLevel、非近端呼叫、匿名呼叫受保護操作，錯誤放行次數須為 0。
