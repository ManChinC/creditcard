## C. 風險記錄（助理觀察，非使用者決定）

1. **瀏覽器端無法保護祕密。** 公開層的 accessRequirement 檢查在使用者瀏覽器內執行，不具信任邊界；因此公開層僅能是匿名操作，所有需保護的操作（含 LLM）只在本機服務（FR-045 已規定）。
2. **兩個執行器的行為可能不一致。** 僅能靠一致性測試案例擋；測試案例須包含拒絕情境與邊界值。
3. **公開 JSON 的完整性。** 訪客無從驗證下載資料是否被託管服務竄改；FR-048 規定載入時經 Validator 驗證 schema，但 schema 驗證不等於內容真實。是否需簽章：`[TBD]`。
4. **貼上內容的注入。** LLM 輸出可能含惡意字串；FR-018、FR-025 規定當資料處理並嚴格驗證，須在 UI 層同樣避免以網頁語法渲染（見 contracts/validator-contract.md）。
